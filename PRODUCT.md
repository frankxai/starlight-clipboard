# Starlight Clipboard

Author: Codex. Created: 2026-11-01. Revision: v1.
Source: Frank's capture, music, liquid-glass and multi-machine requests; README.md,
issue #4 and installed local beta. Review state: existing product truth, mobile extension in development.

Frank wants to recover copied ideas and creative prompts by date, application and
use case, then file chosen work into the existing memory and prompt systems.
The primary audience is the operator and creators who move between Windows PCs
and an Android phone. Capture must remain useful without a model or cloud account.

The accepted world is calm Starlight liquid glass with a creative-studio character:
ink, warm readable text, restrained amber actions and cyan health. DESIGN.md and
the existing library are visual authority. This work extends that identity.

Windows keeps the existing native collector, SQLite originals, authenticated
loopback library, explicit SIS filing and existing encrypted backup integration.
Nexus and Command Center remain their own accepted applications. No second
account authority, memory service, scheduler or gateway belongs in this product.

Mobile's first useful job is to accept a deliberate Paste or Android Share,
commit it offline, recover unfinished text, browse retained originals and export
an interoperable private handoff. The layout leads with capture, then the library;
desktop uses a quiet connection sidebar. Text stays selectable, controls work by
touch and keyboard, and high-frequency actions have immediate state changes.

A normal Android app cannot observe arbitrary background clipboard copies on
Android 10+. Microsoft SwiftKey is an optional latest-clip transport, not a durable
archive. The phone's browser archive, Windows archive and Microsoft cloud history
must be labeled separately. Account/device sync, signed native apps and hardware-
loss recovery are incomplete until their actual acceptance tests pass.

There are no customer counts, measured commercial claims, prices, paid cloud
inference or public release claims. Physical-phone behavior requires a phone;
synthetic browser checks establish only their stated scope. Continuous encrypted
sync remains a shared-platform stage with approved identity and key recovery.
